# Design

## Context

`cf-notepad` (`wiki.david888.com`) runs on Cloudflare Workers (`itty-router`), KV (`NOTES`, `SHARE`), R2 (`IMAGES`), and optional D1 (`NOTE_HISTORY_DB`, plus custom bindings in `wrangler.owner.toml`). Key codebase constraints verified during dual reviews:
- Share outputs currently leak `path` or full `metadata` via `src/templates/base.js:543`, `src/templates/common.js:737`, `src/index.js:1980, 2073, 2107, 2119, 2144, 2420, 2423, 2501, 2530, 2848`, and `Seal` status templates (`src/templates/pages.js`).
- `src/templates/base.js:159-164, 210, 1206, 1340` and `src/index.js:3549, 4011` accept arbitrary `theme` strings and serialize/interpolate `pageTheme` without `ALL_PREVIEW_THEMES` allowlisting or `<script>`-safe escaping across Block/Canvas/Whiteboard/Markdown views.
- `src/templates/base.js:1240, 1255, 1311, 8732, 8750, 1402, 9887, 9947, 10043`, `static/js/block-view.mjs:29`, and `static/js/share-annotations.mjs:1289` contain raw `innerHTML` sinks or unsafe fallback when `DOMPurify` is absent.
- `src/index.js:117, 295-321, 3708-3718` and `src/mcp_server.mjs:414, 427` generate 6-char `shareSlug` (`${path}-...` fallback) with un-CAS'd GET `ensureShareMetadata`, `src/storage_driver.mjs:237, 255` issues background `ON CONFLICT(share_id) DO UPDATE` self-heals, and `wrangler.toml:31-33` sets `SCN_ENABLE_TURNSTILE="1"` while leaving `SCN_TURNSTILE_SECRET` optional in `docs/INSTALLATION.md`.
- `src/storage_driver.mjs:87-117, 463` in `auto` mode swallows D1 write errors while writing KV and overwrites `metadata` blobs without CAS/versioning; `src/note_history.mjs:117-190` throttles, counts, prunes, and deletes by `path` only; `src/note_stats.mjs:1` reads `APP_DB || NOTE_HISTORY_DB`.
- `src/annotation_data.mjs:259-282, 360-379` soft-deletes thread messages without setting `is_resolved`, letting `addAnnotationMessage` reopen soft-deleted threads.
- `src/index.js:353, 1156, 1942, 3883` mint/check `auth` and `cn_author_*` JWTs without `noteUid`.
- `src/constant.js:39-46` uses `SCN_ENABLE_TURNSTILE`, `SCN_TURNSTILE_SITE_KEY`/`TURNSTILE_SITE_KEY`, and `SCN_TURNSTILE_SECRET`/`TURNSTILE_SECRET`.
- `src/helper.js:32, 228` (`returnPage` ignores `headers.status`; `deleteEmptyPages` checks emptiness then deletes by `path`), and `package.json:85-88` only runs `db:init` on `deploy`.

See `proposal.md` and `docs/designs/concepts_brief.md` for motivation and brainstorm history.

## Goals / Non-Goals

**Goals:**
- Deliver v1 complete in one release with all Round 1–8 P0/P1/P2 findings resolved: shared hardened WebAuthn parser core with immutable `BE` parity, nonce-locked `db.batch` transactions across registration, login, step-up, add, and remove, shared Turnstile tri-state policy (aligned with stock `wrangler.toml`) + atomic rate limits, decoupled `isNotesRegistryEnabled()` vs `isAccountFeatureEnabled()` predicates, `delete_nonce`-locked D1 delete+tombstone + `__legacy__` KV-mirror suppression, zero shared KV `path` wipes, legacy active/terminal share cutover + `is_csprng_v1` provenance + `shareOpNonce`-locked share batches + `revoked_reason`, metadata-only authoritative share projections, `note_history_meta` UID isolation with fail-closed legacy history hiding (`SCN_LEGACY_HISTORY_RETENTION_DAYS`), crash-safe single-DB atomic / split-DB staged guest import, non-reopenable soft-deleted annotations + `DELETE /api/account/annotations/:messageId`, `theme` allowlisting + inline-script safe serialization + fail-closed SVG/HTML sanitization, and aligned per-DB schemas.
- Modularize new code into `src/webauthn_core.mjs`, `src/account_data.mjs`, `src/account_routes.mjs`, `src/circle_routes.mjs`, `src/templates/space.js`, `src/templates/circle.js` (via `src/template.js`), and `static/js/account-*.mjs`.

**Non-Goals:**
- Email/phone/SSO auth, account recovery if all Passkeys are lost, REST API / MCP personal attribution tokens (v2), WebTalk integration, multi-persona avatars/bios, or cloud autosave persistence of unpublished drafts (`share !== true`).

## Decisions

### 1. Hardened Shared WebAuthn Core (`src/webauthn_core.mjs`), Nonce-Locked `db.batch` & Strict Turnstile
- **Shared Parser Core**: Bounded CBOR decoding (depth `<= 8`, bounded array/map counts, strict bounds), strict ASN.1 DER parsing (no 64-byte bypass, bounded `r`/`s`), `authDataBytes.length >= 37`, constant-time `authData.rpIdHash === SHA-256(expectedRpId)`, `clientData.type === 'webauthn.create'` (registration/add) or `'webauthn.get'` (login/step-up), `UP` (`0x01`) + configurable `UV` (`0x04`, required for user accounts), `crossOrigin !== true`, explicit `rpId`/`origin` allowlist (`localhost` dev supported), `parsed.credentialId` + `rawId`, `response.userHandle` match, and COSE `ES256 (-7)` + `RS256 (-257)` (`P-256` raw / `SPKI`). Refactor `src/fido_auth.mjs` to use this hardened parser core (`requireUserVerification: false` to preserve existing Admin FIDO behavior, which today checks only `UP` and supports `ES256`, while inheriting bounded CBOR/DER/origin/`rpIdHash`/`clientData.type` protections and keeping Admin KV credentials).
- **Challenge `binding_hash` & Immutable `BE` Parity / Stored-Attribute Counter Policy**: Define `binding_hash = SHA-256(origin + '\n' + rpId + '\n' + purpose + '\n' + (sessionId || ''))`. Reject `BE = 0, BS = 1` AND reject ANY assertion where `authData.be !== storedCredential.backup_eligible`. Select counter policy strictly from **stored `backup_eligible`**: `backup_eligible = 1` allows `0` or non-monotonic counters; `backup_eligible = 0` allows `assertedCount >= 0` when `storedCount === 0` and requires `assertedCount > storedCount` when `storedCount > 0` (rejecting regressions).
- **Session Cookie & Request Bounds**: Host-scoped `cn_account_session` cookie (`HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000`, adding `Secure` on HTTPS requests); enforce `revoked_at IS NULL AND expires_at > unixepoch()` on every read/write; cap auth/account/space/circle JSON request bodies at `<= 32 KB` before `JSON.parse` with strict base64url field length limits.
- **Deterministic Step-Up Purpose & Nonce-Locked Conditional `db.batch` (Zero Mutations on Failure)**:
  - Use distinct challenge `purpose` values `'passkey_add_stepup'` and `'passkey_remove_stepup'` so `stepup/verify` sets `stepup_grants.action` directly from the locked `auth_challenges.purpose` (never from unverified request input). Lock the governing token with a fresh CSPRNG `commitNonce` first so Steps 2..N predicate on `= commitNonce`:
  - **Initial Registration (`register/verify`)**:
    1. Lock challenge (`UPDATE auth_challenges SET consumed_nonce = ? WHERE challenge = ? AND purpose = 'register' AND binding_hash = ? AND user_handle = ? AND consumed_nonce IS NULL AND expires_at > ? AND NOT EXISTS (SELECT 1 FROM account_passkeys WHERE credential_id = ?)` + when Turnstile `enabled`: `AND NOT EXISTS (SELECT 1 FROM used_turnstile_tokens WHERE token_hash = ?)`).
    2. (When Turnstile `enabled`) `INSERT INTO used_turnstile_tokens (...) SELECT ... WHERE EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?)`.
    3. `INSERT INTO accounts (id, user_handle, nickname, created_at, updated_at) SELECT ?, ?, ?, ?, ? WHERE EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?)`.
    4. `INSERT INTO account_passkeys (...) SELECT ... WHERE EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?)`.
    5. `INSERT INTO account_sessions (...) SELECT ... WHERE EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?)`.
    6. `DELETE FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?`.
    Verify `results[0].meta.changes === 1` and session insert `changes === 1` before setting `cn_account_session`.
  - **Login (`login/verify`)** & **Step-Up Grant Issue (`stepup/verify`)**:
    0. Pre-CAS Credential & Account Lookup + Monotonicity Check: `SELECT p.credential_id, p.account_id, p.public_key_spki, p.algorithm, p.sign_count, p.backup_eligible, a.user_handle FROM account_passkeys p JOIN accounts a ON a.id = p.account_id WHERE p.credential_id = ?` (plus `AND p.account_id = ?` for step-up). Verify signature, `BE === p.backup_eligible`, `response.userHandle` (when present) matches `a.user_handle`, and stored-`backup_eligible` monotonicity in JS between `storedCount = p.sign_count` and `assertedCount` (`p.backup_eligible === 0`: `storedCount === 0` permits `assertedCount >= 0`; `storedCount > 0` requires `assertedCount > storedCount`). Bind `resolvedAccountId = p.account_id` (`a.user_handle = ?` binds Step-0-resolved `a.user_handle` for `login` and session/challenge `user_handle` for `stepup`), `backup_state = authData.bs ? 1 : 0`, and `storedCount = p.sign_count` as the SQL compare-and-swap precondition below (NOT `assertedCount`).
    1. `UPDATE auth_challenges AS c SET consumed_nonce = ? WHERE c.challenge = ? AND c.purpose = ? AND c.binding_hash = ? AND COALESCE(c.account_id, '') = ? AND COALESCE(c.session_id, '') = ? AND c.consumed_nonce IS NULL AND c.expires_at > ? AND EXISTS (SELECT 1 FROM account_passkeys p JOIN accounts a ON a.id = p.account_id WHERE p.credential_id = ? AND p.account_id = ? AND a.user_handle = ? AND p.backup_eligible = ? AND (p.backup_eligible = 1 OR p.sign_count = ?) AND (? = 'login' OR p.account_id = c.account_id))` (where `p.sign_count = ?` binds pre-CAS `storedCount`; plus for `'passkey_add_stepup'` and `'passkey_remove_stepup'`: `AND EXISTS (SELECT 1 FROM account_sessions s WHERE s.id = c.session_id AND s.account_id = c.account_id AND s.revoked_at IS NULL AND s.expires_at > ?)`).
    2. `UPDATE account_passkeys SET sign_count = ?, backup_state = ?, last_used_at = ? WHERE credential_id = ? AND account_id = ? AND (backup_eligible = 1 OR sign_count = ?) AND EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?)` (binding `assertedCount` and `authData.bs ? 1 : 0` for `SET`, and `storedCount` for CAS guard).
    3. `INSERT INTO account_sessions (...) SELECT ... WHERE EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?) AND EXISTS (SELECT 1 FROM account_passkeys WHERE credential_id = ? AND account_id = ? AND (backup_eligible = 1 OR sign_count = ?))` (or for step-up: `INSERT INTO stepup_grants (id, account_id, session_id, action, binding_hash, expires_at) SELECT ?, c.account_id, c.session_id, CASE c.purpose WHEN 'passkey_add_stepup' THEN 'add' ELSE 'remove' END, c.binding_hash, ? FROM auth_challenges c WHERE c.challenge = ? AND c.consumed_nonce = ?`).
    4. `DELETE FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?`.
    Verify `results[0].meta.changes === 1 && results[1].meta.changes === 1` (plus session/grant insert `changes === 1`; `stepup/verify` rejects assertions belonging to another account with `0` changes, and concurrent `sign_count` races fail CAS cleanly without creating a session or grant).
  - **Passkey Add (`add/verify`)**:
    1. `UPDATE auth_challenges SET consumed_nonce = ? WHERE challenge = ? AND purpose = 'register_add' AND stepup_grant_id = ? AND binding_hash = ? AND account_id = ? AND session_id = ? AND consumed_nonce IS NULL AND expires_at > ? AND EXISTS (SELECT 1 FROM stepup_grants g WHERE g.id = ? AND g.action = 'add' AND g.consumed_nonce IS NULL AND g.account_id = ? AND g.session_id = ? AND g.binding_hash = ? AND g.expires_at > ?) AND EXISTS (SELECT 1 FROM account_sessions s WHERE s.id = ? AND s.account_id = ? AND s.revoked_at IS NULL AND s.expires_at > ?) AND NOT EXISTS (SELECT 1 FROM account_passkeys WHERE credential_id = ?)` (binding TWO distinct server-recomputed hashes: `c.binding_hash = SHA-256(origin, rpId, 'register_add', sessionId)` for the registration challenge and `g.binding_hash = SHA-256(origin, rpId, 'passkey_add_stepup', sessionId)` for the originating step-up grant!).
    2. `UPDATE stepup_grants SET consumed_nonce = ? WHERE id = ? AND consumed_nonce IS NULL AND EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?)`
    3. `INSERT INTO account_passkeys (...) SELECT ... WHERE EXISTS (SELECT 1 FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?) AND EXISTS (SELECT 1 FROM stepup_grants WHERE id = ? AND consumed_nonce = ?)`
    4. `DELETE FROM auth_challenges WHERE challenge = ? AND consumed_nonce = ?`
    5. `DELETE FROM stepup_grants WHERE id = ? AND consumed_nonce = ?`
    Verify `results[0].meta.changes === 1 && results[2].meta.changes === 1` (if any precondition fails, Step 1 updates 0 rows -> zero mutations and challenge/grant stay unconsumed).
  - **Passkey Remove (`remove`)**:
    1. `UPDATE stepup_grants SET consumed_nonce = ? WHERE id = ? AND action = 'remove' AND consumed_nonce IS NULL AND account_id = ? AND session_id = ? AND binding_hash = ? AND expires_at > ? AND EXISTS (SELECT 1 FROM account_sessions s WHERE s.id = ? AND s.account_id = ? AND s.revoked_at IS NULL AND s.expires_at > ?) AND EXISTS (SELECT 1 FROM account_passkeys p WHERE p.credential_id = ? AND p.account_id = ?) AND (SELECT COUNT(*) FROM account_passkeys WHERE account_id = ?) > 1` (recomputing `g.binding_hash = SHA-256(origin, rpId, 'passkey_remove_stepup', sessionId)`).
    2. `UPDATE account_sessions SET revoked_at = ? WHERE account_id = ? AND id != ? AND revoked_at IS NULL AND EXISTS (SELECT 1 FROM stepup_grants WHERE id = ? AND consumed_nonce = ?)`
    3. `DELETE FROM account_passkeys WHERE credential_id = ? AND account_id = ? AND (SELECT COUNT(*) FROM account_passkeys WHERE account_id = ?) > 1 AND EXISTS (SELECT 1 FROM stepup_grants WHERE id = ? AND consumed_nonce = ?)`
    4. `DELETE FROM stepup_grants WHERE id = ? AND consumed_nonce = ?`
    Verify `results[0].meta.changes === 1 && results[2].meta.changes === 1`.
- **Shared Turnstile Tri-State Policy (`resolveTurnstilePolicy()`) & Rate Limits**:
  1. `SCN_ENABLE_TURNSTILE` in `['0', 'false']` -> `disabled`.
  2. Else if `SCN_ENABLE_TURNSTILE` non-empty and not `'1'` -> `misconfigured` (`503`).
  3. Else if `SCN_ENABLE_TURNSTILE === '1'` -> `enabled` iff BOTH `getTurnstileSiteKey()` and `getTurnstileSecret()` non-empty, else `misconfigured` (`503`).
  4. Else (`SCN_ENABLE_TURNSTILE` empty) -> both keys non-empty => `enabled`; one key non-empty => `misconfigured` (`503`); both empty => `disabled`.
  `enabled` uses strict `verifyTurnstileTokenStrict(token, remoteip, { expectedHostname: new URL(origin).hostname, expectedAction: 'passkey_register' })` (which explicitly ignores `SCN_TURNSTILE_FAIL_OPEN` and `cn_turnstile_clearance` cookies, failing closed on upstream/hostname/action/replay errors) + D1 `used_turnstile_tokens`. Both register and login challenge endpoints enforce atomic `auth_rate_limits` and pending-challenge caps before writing `auth_challenges`. Align `wrangler.toml` (`SCN_ENABLE_TURNSTILE = "0"` and blank site key unless operator pairs `SCN_TURNSTILE_SECRET`) and `docs/INSTALLATION*.md` so fresh one-click deploys never boot into `503 misconfigured`, and require secret bindings (no plaintext secrets in `[vars]`) in operator Wrangler configs.

- **Atomic Quotas**: `20` circles/account (`INSERT INTO share_circles (id, account_id, public_token, name, is_enabled, created_at, updated_at) SELECT ?, ?, ?, ?, 0, ?, ? ### 3. Authoritative `notesDb`, `delete_nonce` Tombstones, History Isolation & Canonical Share Registry
