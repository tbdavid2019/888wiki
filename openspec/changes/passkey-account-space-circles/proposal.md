# Proposal

## Why

`cf-notepad` (`wiki.david888.com`) currently relies on anonymous URLs, browser-local `localStorage` (`cf-notepad:share-history`), and single-device cookies (`cn_author_*`, `deleteToken`), which prevents users from organizing their creations, edits, bookmarks, and built-in annotations across devices or sharing curated topic lists. Introducing a zero-privilege, Passkey-only account and personal space layer solves cross-device personal organization and shareable topic collections while keeping anonymous zero-login authoring and note-level `pw`/`vpw` password locks completely intact.

## What Changes

- Introduce Passkey-only accounts using WebAuthn Discoverable Credentials (`residentKey: required`, `userVerification: required`) with a single 40-character nickname, step-up re-authenticated multi-device Passkey add/remove management (atomic minimum-1 Passkey enforcement), and future-proof `accounts` + `account_passkeys` (1:N) D1 tables.
- Harden WebAuthn verification (`src/webauthn_core.mjs`) with bounded CBOR/DER parsing, `UV` flag checks, `BE`/`BS` synced-passkey `signCount` handling, COSE `ES256`/`RS256` support, D1-backed multi-field atomic `auth_challenges`, single-use strict Turnstile registration guard + atomic IP-hash rate limits, and isolated revocable `cn_account_session` cookies; share the hardened parser core with Admin FIDO (`src/fido_auth.mjs`) while documenting Admin's remaining KV boundaries.
- Add a private cross-format (`markdown`, `block`, `canvas`, `whiteboard`) Personal Main Space (`/_space`) indexing created, browser-edited, bookmarked, and account-annotated notes, with strict `edit` vs `share_only` capability separation, immutable `note_uid` anti-collision (fail-closed across D1/KV), non-sensitive `titleSummary` metadata + uniform masking for inaccessible/protected items, and confirmation-based guest history import. Browser-edited unpublished drafts (`share !== true`) remain strictly local in `offlineStore` and are never uploaded or indexed into cloud `/_space`.
- Add multiple toggleable Public Share Circles (`/c/:publicToken`) using rotatable `public_token` URLs (defaulting new circles to OFF for private-first safety), private-by-default manual bookmarking, strict live authoritative filtering excluding unpublished, `vpw`-locked, Seal (`burn`/`timelock`/`deadman`), expired, or missing-`note_uid` notes, and emitting only high-entropy (`>= 16` bytes) canonical non-path `/share/:shareId` links.
- Integrate built-in Line-Anchored Annotations (`annotation_messages`) via an atomic same-batch `account_annotation_links` + `annotation_thread_meta` sidecar design (preserving `db:init` idempotency): isolate threads across 4-char slug reuse via `note_uid`, allow signed-nickname snapshot posting with single-message cross-device self-deletion (including account-scoped `DELETE /api/account/annotations/:messageId` with zero public `account_id`), reject replies on soft-deleted threads, support unlinked anonymous comments, and verify DB `root_message_id` on thread deletion.
- Fix prerequisite client bugs, share path-capability leaks, and same-origin XSS vectors before issuing `Path=/` session cookies: gate `base.js:5767` `share-history:created` on `isEdit`, remove unauthenticated `/:path` / secret metadata leaks in `common.js:737`, `index.js:2144` Markdown export, `index.js:2423` `/reveal` JSON, `handleSharePdfExport`, and Seal status pages, allowlist persisted `theme` values and use safe inline script serialization across Markdown/Block/Canvas/Whiteboard renders, fail-closed SVG sanitization across presentation (`Mermaid` + `Pele`), block-view (`static/js/block-view.mjs` `Pele`), diagram renderers (`base.js:1240-1315`), book print/export HTML, and error messages, enforce `SCN_ENABLE_WEBTALK`, apply strict CSP / `Referrer-Policy` / SW cache bypass, fix `returnPage` + `Page404` HTTP status (`GET`/`HEAD`), and enforce `RESERVED_SLUGS` + dynamic `SCN_ADMIN_PATH` checks.
- Decouple D1 notes-registry authority (`isNotesRegistryEnabled()`) from account readiness (`isAccountFeatureEnabled()`), cleanly disabling account features in pure KV (`SCN_STORAGE_DRIVER="kv"`) or missing-`accountDb` (`APP_DB || NOTE_HISTORY_DB`) deployments while preserving anonymous KV/history/stats/annotation flows, aligning stock Turnstile/config defaults in `wrangler.toml`, `db:init`, `db:init:owner`, `deploy:owner`, `publish`, `/api/health`, `README.md`, `README.zh-TW.md`, `docs/INSTALLATION*.md`, and `wrangler.toml.example`.

## Capabilities

### New Capabilities
- `passkey-accounts`: Passkey-only registration/login (Discoverable Credentials), hardened WebAuthn verification (shared parser core with Admin FIDO), D1 atomic multi-field challenges, step-up single-use grant multi-device Passkey management (minimum-1 enforcement), `cn_account_session` revocation, single nickname (`<= 40` chars), strict Turnstile + atomic rate limiting, and graceful D1-absent disabling.
- `personal-space`: Private cross-format Personal Main Space (`/_space`), zero-privilege multi-facet indexing (`created`/`edited`/`bookmarked`/`annotated`), `edit` vs. `share_only` path-leak prevention (`note_uid` fail-closed + uniform inaccessible-item masking), local-only autosave draft boundary, and confirmation-based guest history import.
- `public-share-circles`: Multiple named toggleable public Share Circles (`/c/:publicToken`) with rotatable `public_token` URLs, private-first creation/bookmarking defaults, canonical high-entropy non-path `/share/:shareId` issuance/outputs, and live authoritative D1/KV-reconciled eligibility enforcement.
- `account-annotations`: Atomic same-batch `account_annotation_links` + `annotation_thread_meta` attribution and `note_uid` thread isolation for built-in Line-Anchored Annotations, explicit signed-nickname snapshot vs. unlinked anonymous posting mode, single-message cross-device self-deletion without public `account_id` correlation, and DB-verified `root_message_id` thread deletion.
- `share-security-hardening`: Prerequisite fixes for all share edit-path leaks (`common.js:737`, `index.js:2144`, `index.js:2423`, `handleSharePdfExport`, Seal status pages), `share-history:created` recording guard, fail-closed SVG/HTML XSS sanitization across presentation, block-view, diagrams, and book export, strict CSP/`Referrer-Policy`/`SCN_ENABLE_WEBTALK`, `returnPage`/`Page404` HTTP status + `HEAD` parity, `RESERVED_SLUGS` (REST + MCP), `robots.txt`, and `static/sw.js` cache exclusions.
